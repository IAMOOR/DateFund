💡 **What:** Replaced the `getEventsForDay` helper function (which filtered all events and parsed their ISO dates on every render for every day) with a `useMemo` map `eventsByDate` that parses and categorizes events upfront. Removed unused `isSameDay` and `addDays` imports.
🎯 **Why:** The previous logic had an $O(N \times D)$ complexity during render, where $N$ is the total number of events and $D$ is the number of days rendered (usually 35-42). As events scale, this severely blocks the main thread during navigation. By converting it to a precomputed lookup map ($O(N)$ once, then $O(1)$ lookup per day), we drastically decrease rendering time overhead.
📊 **Measured Improvement:** A custom benchmark running 1,000 events across a 35-day grid simulated 100 render cycles.
- **Baseline (Original):** ~13.647s
- **Optimized (New Map Lookup):** ~755ms
- **Result:** ~94% reduction in execution time for the event aggregation logic.
